A repository organized by responsibility

Proposal only — nothing has been moved. One authored implementation per responsibility, one generated-output root, explicit dependency and evidence boundaries. The folder tree below is the proposed destination, not the current filesystem.

Correction to the previous audit: the current MiSTer template checkout is clean at pinned revision 3ea1134c. The experimental ascal.vhd horizontal-limit patch was archived and reverted. Historical candidate copies are evidence, not current framework modifications.

The navigation rule

Hardware → hardware/ · host software → software/ · cross-system checks → verification/ · commands → workflows/ · dependencies → vendor/ · generated files → build/. Language is a subdirectory when it clarifies the implementation, not a competing top-level architecture. Scala, DSLX and handwritten RTL are complementary layers, not three renderers.

SpinalVoodoo/the project
README.md, ARCHITECTURE.md, AGENTS.md, Makefile, lockfiles and root environment entrypoints stay here. README is the navigation map; Makefile keeps the public command names. No parallel legacy renderer hierarchy.
hardware/AUTHOREDrenderer, shared glue, board integration
renderer/dslx/the rendering implementation
Move xls/dslx/*.x here: control, rasterization, interpolation, texture/cache and pixel processing. Keep inline DSLX tests with the implementation. Do not invent separate modules just to fill the tree.
shared/scala/reusable scanout and memory-transfer glue
Move shared src/voodoo/{framebuffer,hdmi}, configuration/generation support and genuinely shared Avalon adapters here. Preserve existing Scala packages initially. A DE10-named adapter also consumed by MiSTer belongs here after consumer verification, not after a filename-only decision. shared/tests/ holds its Scala simulation/formal tests.
shared/rtl/handwritten integration primitives
Handwritten memories, palette storage and framebuffer/texture adapters currently under hw/de10/xls/ that both platforms actually consume. XlsPaletteMemory.sv is an integration memory, not a second renderer. Tests live in shared/tests/; compiler-generated module bodies never go here.
platforms/de10/standalone DE10 board boundary
scala/: DE10 scanout/top generators and DDR benchmark. rtl/: authored XlsDe10Top.sv and board wrappers. quartus/: authored QSF/SDC/Tcl and pin assignments. qsys/: input system descriptions only. linux/: device-tree inputs. tests/: platform Scala and MMIO RTL tests. Generated Qsys systems, reports and handoffs move to build only after regeneration/boot proof.
platforms/mister/MiSTer shell and platform integration
scala/: src/voodoo/mister/ including mailbox, reset draining, DDR arbitration and scanout. rtl/: authored SpinalVoodoo.sv. quartus/: constraints, project inputs, timing scripts and file lists. tests/: platform testbench, simulation stubs and Scala regressions. Framework implementation remains a pinned dependency, not copied into this authored tree.
software/AUTHOREDCPU-side runtime, integration and simulation
runtime/mister/memory ownership and ordered host transport
Move emu/mister/mister_{memory,mailbox,runtime}.{c,h} and their tests here. One runtime shared by DOSBox and Glide; do not duplicate it per frontend. Keep native tests under tests/ inside this component.
integrations/glide/owned Glide adapter code
Own glide_guest, glide_presenter, harness/demo and relevant tests from emu/mister/. Upstream Glide stays under vendor. Build integration files belong here; upstream-derived edits remain explicitly distinguishable from new adapter code.
integrations/dosbox/DOSBox input, display and Glide bridge
Own DOSBox input/output adapters, Glide/jitdump headers, smoke helper and their tests. Put launch configuration alongside the integration. The full DOSBox-X checkout is a pinned vendor source, not a second maintained emulator.
simulation/xls/hosted renderer execution
Consolidate maintained XLS harness/AOT socket bridge code from emu/sim/harness/ and runtime C++ currently hidden under nix/. Nix should describe the toolchain, not hide product runtime implementation. Generated AOT objects and Verilator output go to build.
trace/one trace format and shared replay helpers
Move emu/trace/ here. Capture, simulation replay and board replay consume the same format/helpers; avoid creating a board-specific duplicate trace library.
reference/independent correctness oracle wrapper
Own emu/test/ref_model.*, 86Box stubs and the wrapper build. Keep pinned 86Box itself under vendor. Third-party stb_image_write.h gets explicit vendor attribution instead of masquerading as owned reference code.
verification/AUTHORED + FIXTUREStests spanning component boundaries
integration/: real-Glide, reference-vs-RTL and hardware replay tests, including trace_test.cpp and proc-network testbenches. fixtures/traces/: existing trace binaries, states and reference images. Unit tests move with their owners; this directory is not a second catch-all unit-test tree. Test runners aggregate colocated suites without changing assertions.
workflows/AUTHOREDexecutable operations, grouped by task
build/, check/, board/, package/, run/. Move maintained scripts by their main operation. Shared shell helpers sit beside callers. Related workflow Python tests live in workflows/tests/. Root Make targets preserve the familiar public interface; no permanent second copy in scripts.
diagnostics/AUTHOREDprofiling, board utilities and repository inspection
profiling/: stack collection/decoding, JIT tooling, HTML reports and profiling workload tests. board/: canonical MMIO, DDR and framebuffer tools, including recovery-critical de10_bridge_fix.c. repository/: inventory and static tree generator/templates/tests. Probes under review stay identifiable; lack of a caller is not deletion proof. No new generic plugin framework.
vendor/DEPENDENCIESupstream identities and deliberate local deltas
sources.json records exact pins, licenses and checkout identities. glide/ and 86box/ retain existing upstream provenance/submodule behavior. patches/{glide,dosbox-x,mister,xls}/ stores adopted downstream deltas when reproducible application is proven. Large fetched checkouts live in build/deps/. Do not convert the currently vendored Glide tree into “vanilla + patches” until its full local delta and builds are verified. There is currently no adopted modified MiSTer scaler patch.
environment/AUTHOREDtoolchain definitions, not runtime code
Nix package definitions and Quartus/XLS shell support from nix/. Root flake.nix, devenv.nix and lockfiles remain discoverable entrypoints. Compiler/toolchain patches live in vendor/patches; C++ renderer-host bridge code moves to software/simulation/xls.
docs/AUTHOREDarchitecture, operation and historical decisions
architecture/, guides/, reference/, experiments/. Keep the Screamer 2 journal and preserve its historical claims with dated corrections. Link raw evidence, never copy it into guides. Consolidate stale architecture documents into one maintained narrative with migration redirects where needed. Learning tours remain optional .learning/ documents, not another source root.
build/IGNORED · REGENERATABLEall normal build outputs and fetched working dependencies
generated/{xls,scala,qsys}/, simulation/, quartus/{de10,mister}/, host/, test-results/, packages/, deps/. Generated RTL includes today’s tracked xls/rtl/*.v; retain reviewed snapshots until clean generation proves replacement safe. Quartus working projects copy/reference authored inputs and write only here. Fetched dependency checkouts are reproducible from pins but must be checked for dirt before removal. Tool-managed .direnv/.devenv caches are explicit exceptions where tools require them.
releases/IMMUTABLE MANIFESTSexact signed release identity
Small tracked manifests: source commits/patch hashes, generator/tool versions, constraints, runtime/bitstream hashes, timing and correctness evidence links, and restoration instructions. Large immutable bundles live in separate archive storage. A manifest must not imply the current experimental tree reproduces a signed build unless verified.
experiments/EVIDENCE INDEXfailed and successful candidates, never normal build cache
Small tracked indexes and reproducing recipes grouped by experiment/candidate. Raw captures, source snapshots, failed logs and RBFs remain preserved in checksum-verified archive bundles. Existing output/ stays untouched during transition; archive paths/storage location are selected explicitly, not guessed. Experimental palette/arbiter source remains with its owning component until an explicit retirement decision; timing failures do not justify deleting necessary platform modules.

How a contributor would navigate

  • Fix a pixel or texture bug: hardware/renderer/dslx → inline tests → verification/integration replay.
  • Debug a mailbox stall: software/runtime/mister → its tests → hardware/platforms/mister/scala → diagnostic profiling.
  • Change DE10 pins or clocks: hardware/platforms/de10/quartus → workflows/build → build/quartus/de10.
  • Investigate DOSBox LFB behavior: software/integrations/dosbox + glide → colocated tests → vendor patches only if the upstream guest bridge changes.
  • Find what actually shipped: releases manifest → exact archived bundle, not the newest file in build.

Migration order and acceptance gates

  1. Establish a baseline. Record tracked/untracked ownership and hashes, pins, signed artifacts and actual generator/consumer paths. Correct stale inventory claims. Preserve evidence before any relocation.
  2. Create the source map first. Move authored code by component with all direct build/import/file-list consumers in the same change. Preserve Scala package names initially. One canonical implementation; no duplicate compatibility copies.
  3. Prove a clean generated boundary. Redirect generator outputs and consumers together. Rebuild tracked XLS RTL, Scala RTL and Qsys inputs into build; compare interface/function/replay behavior. Prove boot/handoff regeneration before removing generated handoffs from version control. Never delete the only useful generated snapshot first.
  4. Separate dependencies and packaging. Preserve upstream licenses/submodule identities and local deltas; exercise native, DOS and ARM Glide build paths before removing vendor generations. Verify framework source-preparation guards still reject dirty checkouts.
  5. Validate end-to-end. Run the full Python/native/XLS/Scala suites, lint/formal/replay checks and package smoke tests. FPGA release acceptance still requires the complete timing-signed flow within 900 seconds and board recovery/boot checks; moving files alone earns no hardware signoff.
  6. Move evidence last. Read/restore-test checksummed archives before pruning output. Retain failed experiments and signed candidates. Update documentation, release manifests and the static classification tree to the new paths.

Deliberate limits: this proposal does not authorize deletion, claim release reproducibility, decide which legacy Glide targets are supported, or settle diagnostic recovery coverage. The exact shared-vs-platform RTL split requires consumer verification. No sweeping rewrite, new build framework, new dependencies or guessed archive service is necessary.
